# Hook Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. It will decide whether each batch should run in parallel or serial subagent mode and will pass only task-local context to each subagent. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert Hook from audit persistence into configurable lifecycle automation rules while removing the unused Hook audit table and UI.

**Architecture:** `governance_hook_rule` remains the only Hook configuration table. `HookRuleService.trigger` becomes a pure matcher that returns enabled rules for a lifecycle event, and current chat callers keep treating Hook failures as non-blocking side effects. Admin UI keeps Hook rule CRUD and removes Hook audit fetching/display.

**Tech Stack:** Spring Boot, MyBatis-Plus, PostgreSQL migration SQL, JUnit, React, TypeScript, Ant Design, Vitest.
