# 第一期用户端 UI 设计说明

更新时间：2026-05-13

## 一、文档定位

这份文档用于约束第一期用户端原型图的页面 UI 设计。

它解决的不是产品分期和功能规划问题，而是下面这些问题：

- 页面整体长什么样
- 工作台怎么分区
- 左侧导航和右侧内容怎么组织
- 每个页面应该有哪些内容块
- 卡片、标签、列表、输入框这些组件怎么表现
- 页面切换和状态切换怎么保持一致

这份文档服务于：

- `用户端第一期原型图提示词.md`
- 后续 Web 前端页面实现

## 二、UI 设计目标

第一期用户端 UI 目标只有三件事：

1. 做出“桌面工作台”的感觉，而不是官网首页，也不是普通聊天页
2. 让任务、技能、专家、自动化四个入口在同一套界面体系里成立
3. 让右侧内容区具备明显的“正在处理任务 / 正在查看内容”的工作界面感

## 三、总体界面形态

第一期采用桌面端 Web 工作台布局，设计基准为 `1440 x 1024`。

整体结构固定为四层：

- 顶部细菜单栏
- 左侧固定导航栏
- 右侧主内容区
- 底部固定输入区

整体界面要求：

- 左侧栏固定存在
- 右侧内容区承担主要页面内容
- 页面切换尽量发生在右侧内容区
- 不通过大弹窗承载核心页面
- 不预设具体颜色方案，重点先把结构、层级和块面关系做对
- 所有页面必须复用同一套顶部栏、左侧侧栏、左下角账户区
- 技能页、专家页、自动化页只更换右侧内容区，不重新设计全局壳层
- 全局顶部栏右侧默认留空
- 页面框内部右上角默认不补额外图标组

## 四、全局布局规范

### 1. 顶部细菜单栏

位置：

- 页面最顶部，通栏

内容：

- 品牌区

表现要求：

- 高度较窄
- 更像桌面软件菜单条，而不是官网导航栏
- 不承担主要业务入口
- 在主工作台、技能页、专家页、自动化页中保持完全一致
- 顶部栏右侧保持留白，不放通知、设置、帮助、分享、预览、更多等按钮

### 2. 左侧固定导航栏

位置：

- 页面左侧固定

结构从上到下分为四段：

- 一级入口区
- 任务列表区
- 用户信息区

表现要求：

- 宽度固定
- 始终可见
- 技能、专家、自动化页面也保留该侧栏
- 结构顺序固定，不允许某些页面替换成别的导航结构

### 3. 右侧主内容区

位置：

- 左侧导航右边，占据主要空间

表现要求：

- 作为页面主承载面
- 页面标题、内容区块、卡片列表都在这里完成展示
- 新建任务、任务详情、技能、专家、自动化的主体内容都在这里切换
- 页面内容卡片或页面容器的右上角默认不额外生成图标组

### 4. 底部固定输入区

位置：

- 主工作台底部固定

表现要求：

- 始终贴底
- 作为任务输入主入口
- 附带轻量工具图标即可
- 不要做成独立悬浮聊天窗

## 五、导航系统设计

### 1. 左侧一级入口

一级入口固定为：

- 新建任务
- 技能
- 专家
- 自动化

表现要求：

- 每项包含图标和文字
- 当前页面所在菜单需要有明显选中态
- 菜单排布要简洁，不能过度装饰

### 2. 任务列表区

任务列表区直接展示任务项列表。

任务项表现要求：

- 显示任务名称
- 可带简要状态信息
- 当前选中任务要有明显选中态
- 长标题可截断
- 左侧菜单下方直接展示任务项内容

### 3. 用户信息区

位置：

- 左侧底部

结构：

- 头像
- 用户名

点击后弹出账户菜单卡片。

表现要求：

- 左下角首先表现为“个人头像 + 名字”的信息条
- 不要做成独立小图标
- 不要做成只有数字编号的账户占位块
- 所有页面都复用同一个账户区组件
- 左下角账户区之外，不再额外生成文档入口、帮助入口、工作区入口、项目快捷入口等额外块

## 六、主工作台 UI 设计

主工作台是第一期最重要的页面，右侧主内容区必须支持两种核心状态。

### 1. 空白起始态

触发方式：

- 点击“新建任务”

交互规则：

- 不弹窗
- 不打开模态框
- 不跳到独立新页面
- 直接清空右侧内容区

页面结构：

- 中央欢迎区
- 下方快捷能力卡片区
- 底部固定输入框

欢迎区表现要求：

- 居中
- 文案简洁
- 作为空白工作区起点

快捷能力卡片区表现要求：

- 一排或多列卡片
- 卡片内容简短直接
- 用于表达用户可快速发起的能力方向

建议卡片示例：

- 网页读取
- 调研分析
- 数据挖掘
- 文件管理

### 2. 任务详情态

触发方式：

- 点击左侧任务项

页面结构：

- 顶部任务标题区
- 中部对话与内容区
- 右侧信息侧栏
- 底部固定输入框

顶部任务标题区：

- 显示任务标题
- 显示时间信息

中部对话与内容区：

- 以对话流为主
- 混合展示结构化内容块
- 内容块可包含文档、列表、代码块、分段说明

右侧信息侧栏：

- 待办
- 任务产物
- 参考信息

表现要求：

- 对话区是主视觉重点
- 信息侧栏是辅助区，宽度要收敛
- 整体要有“正在工作”的界面感觉

## 七、技能页 UI 设计

技能页采用“已安装区 + 技能市场区”的上下结构。

### 1. 右侧内容头部

包含：

- 标题：技能
- 副标题：赋予 CodingX 更强大的能力
- 搜索技能输入框
- 添加技能按钮

头部要求：

- 标题区在左
- 搜索和按钮在右
- 结构清晰，不要挤成一行工具栏样式
- 这里只是右侧内容区头部，不替换全局顶部栏

### 2. 已安装区

结构：

- 标题：已安装
- 数量标识
- 横向技能卡片列表

单张卡片字段：

- 图标
- 技能名称
- 标签
- 简介

表现要求：

- 卡片更扁一些，适合横向排布
- 一眼能看出这是“已经可用”的能力
- 至少展示 5 个示例

### 3. 技能市场区

结构：

- 顶部标签页：推荐 / SkillHub / 套件
- 分类筛选标签
- 多列技能卡片网格

分类标签包括：

- 全部
- 生活服务
- 开发工具
- 内容创作
- 数据分析
- 效率工具
- 办公协同
- 商业运营
- 知识学习

单张市场卡片字段：

- 图标
- 技能名称
- 简介
- 安装入口

表现要求：

- 信息密度要高于已安装区
- 更接近“应用市场”浏览体验
- 卡片数量要足够丰富，不能只有少量占位项

## 八、专家中心页 UI 设计

专家中心页采用“角色团队 + 角色列表”的双模块结构。

这里的“专家”不是现实世界里的顾问名片，也不是人物档案页，而是平台内可直接使用的预设角色。

### 1. 右侧内容头部

包含：

- 标题：专家中心
- 副标题：按行业分类浏览角色型专家，为任务分配合适角色
- 搜索框

### 2. 专家团模块

结构：

- 模块标题：专家团
- `Beta` 标识
- 行业分类标签
- 多列卡片网格

卡片字段：

- 角色团队名称
- 角色标签
- 简介
- 角色头像组
- 使用量
- 使用按钮

表现要求：

- 卡片比技能卡片更大
- 要明显看出这是“角色组合”而不是企业组织介绍
- 更接近可直接调用的角色团队模板

### 3. 专家模块

结构：

- 模块标题：专家
- 排序或切换标签：最热 / 最新
- 多列专家卡片网格

卡片字段：

- 角色头像
- 角色名称
- 能力标签
- 角色简介
- 使用量

表现要求：

- 专家卡片视觉层级低于专家团模块
- 但仍要保留足够的信息密度
- 看起来要像“可选角色卡片”，而不是现实人物资料卡

## 九、自动化页 UI 设计

自动化页采用“头部操作区 + 标签页 + 模板区”的结构。

### 1. 右侧内容头部

包含：

- 标题：自动化
- 副标题：配置和管理自动化任务，按计划执行工作流
- 右上角按钮：手动新建 / 在对话中创建

### 2. 标签页区

标签页固定为：

- 已配置
- 执行历史
- 任务模板

默认展示可放在“任务模板”。

### 3. 模板区

结构：

- 多列模板卡片网格

单张卡片字段：

- 图标
- 模板名称
- 模板简介

建议模板示例：

- 每日 AI 新闻简报
- 品牌舆情监控周报
- 每周竞品动态追踪
- 股价监控与预警
- 安全漏洞扫描
- 扫描提交发现 Bug
- 补充测试覆盖
- 每日变更摘要

表现要求：

- 看起来像可复用的任务模板中心
- 不要做成复杂后台表格系统

## 十、账户菜单 UI 设计

点击左下角用户信息区后，弹出账户菜单卡片。

菜单内容固定为：

- 账号头像与昵称
- 设置
- 深色主题开关
- 帮助与反馈
- 检查更新
- 退出登录

表现要求：

- 菜单卡片体量小而清晰
- 信息项纵向排列
- 不加入积分、成长计划、升级按钮等额外内容

## 十一、通用组件规范

第一期原型图里需要统一以下组件表现。

### 1. 搜索框

适用位置：

- 左侧任务搜索
- 技能页搜索
- 专家页搜索

要求：

- 样式统一
- 包含搜索图标
- 输入区高度一致

### 2. 标签页

适用位置：

- 技能页顶部标签
- 自动化页顶部标签

要求：

- 选中态明确
- 非选中态弱化
- 排列紧凑但可点击

### 3. 分类标签

适用位置：

- 技能页分类筛选
- 专家页行业分类

要求：

- 支持多个并列展示
- 当前选中项明确
- 整体更轻量，不喧宾夺主

### 4. 卡片

适用位置：

- 技能卡片
- 专家团卡片
- 专家卡片
- 自动化模板卡片
- 快捷能力卡片

要求：

- 卡片边界清楚
- 内部有稳定的上下信息层次
- 图标、标题、简介、操作入口关系清晰

### 5. 列表项

适用位置：

- 左侧任务项
- 信息侧栏条目

要求：

- 选中态清晰
- 悬停态轻量
- 不能抢主内容区视觉

## 十二、状态设计

第一期原型至少要覆盖以下状态：

- 默认态
- 选中态
- 悬停态
- 空白态
- 已有内容态

重点状态包括：

- 新建任务空白态
- 任务详情态
- 左侧任务选中态
- 当前菜单选中态
- 账户菜单展开态

## 十三、页面一致性要求

所有页面都要保持以下一致性：

- 顶部栏结构一致
- 左侧导航结构一致
- 左下角账户区一致
- 页面头部结构一致
- 卡片语言一致
- 搜索框样式一致
- 标签和筛选控件语言一致

不能出现的问题：

- 技能页像应用市场，但专家页突然变成表格后台
- 主工作台是桌面工作台，自动化页却像完全不同的网站
- 不同页面按钮、输入框、卡片风格差异过大
- 某些页面左下角出现额外入口块，另一些页面只显示头像用户名
- 某些页面重新设计顶部栏，导致全局壳层不统一
- 全局顶部栏右上角被自动补出预览、导出、分享、更多等无关按钮
- 页面内部右上角被自动补出通知、设置、帮助、收藏等无关小图标

## 十四、原型图必须体现的交互

第一期原型图必须明确体现这些交互关系：

1. 点击“新建任务”后，右侧切为空白起始态
2. 点击左侧任务后，右侧切为任务详情态
3. 点击“技能”进入技能页
4. 点击“专家”进入专家中心页
5. 点击“自动化”进入自动化页
6. 点击左下角用户信息区，弹出账户菜单卡片

## 十五、结论

这份 `design.md` 的重点不是定义品牌风格，而是把第一期用户端页面 UI 的骨架、模块、层级和状态关系定下来。

只要原型图严格按照这份文档去表达，后续前端实现时就不会再把“工作台页”“技能页”“专家页”“自动化页”做成四套互相割裂的界面。
