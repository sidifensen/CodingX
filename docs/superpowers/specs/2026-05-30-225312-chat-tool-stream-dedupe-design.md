# Chat Tool Stream Dedupe Design

## 目标

修复模型自主调用本地工具后，同一条助手回复把工具前已经流式输出的开场正文再次输出，导致前端主消息区出现“正文、工具过程、同一正文重复”的问题。

## 根因

`ChatApplicationService.runAiToolAwareLoop` 在模型第一轮输出正文并请求工具后，会把“本轮助手已经向用户流式输出过以下正文”作为系统上下文注入下一轮模型。该提示只能降低重复概率，不能保证模型遵守；当第二轮模型仍从相同开场白开始输出时，`buildStreamHandler.onDelta` 会继续追加并发布该 delta，最终让 SSE、内存缓冲和落库正文全部重复。

## 方案

在后端工具循环中保留“下一轮应跳过的已发布正文前缀”。每次工具调用前如果 `builder` 已有新增正文，就把完整已发布正文写入跳过状态；后续 `onDelta` 先消费该前缀，完全重复的 delta 不发布、不追加，部分重复的 delta 只发布剩余部分，遇到不匹配内容则清空跳过状态并按原样输出。

## 边界

- 只在模型可见工具链路启用前缀跳过；普通聊天流不受影响。
- 只跳过严格匹配的已发布前缀，不做语义相似去重，避免误删用户应看到的新内容。
- 跳过逻辑作用于服务端发布与落库前，确保前端实时展示、SSE 缓冲回放和历史消息内容一致。

## 验证

新增后端单测模拟两轮工具流：第一轮输出开场白并请求工具，第二轮再次输出同一开场白再输出最终结果。测试要求重复开场白只被发布一次，最终落库正文只包含一次开场白。
