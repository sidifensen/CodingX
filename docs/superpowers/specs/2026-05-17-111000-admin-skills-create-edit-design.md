# 管理端技能页新增编辑能力设计

## 1. 背景

用户反馈管理端技能页虽然展示了“创建新技能”按钮，但无法实际新增，且技能卡片无编辑入口，导致技能管理链路中断。

## 2. 目标

1. 管理端 `/skills` 页面支持“新增技能”弹窗。
2. 每个技能卡片支持“编辑技能”弹窗。
3. 提交后调用真实后端接口并刷新列表，确保页面可见新增与编辑结果。
4. 全程使用页面内弹窗，不使用浏览器原生 `alert/confirm/prompt`。

## 3. 方案

### 3.1 页面交互

- 顶部“创建新技能”按钮点击后打开 `新增技能` 弹窗。
- 每个技能卡片新增“编辑”按钮，点击后打开 `编辑技能` 弹窗。
- 编辑模式下“技能编码”只读，避免误改唯一标识。

### 3.2 数据流

- 页面初始化与提交后统一调用 `loadSkills()` 刷新列表。
- 新增提交调用 `AdminChatApi.createSkill(payload)`。
- 编辑提交调用 `AdminChatApi.updateSkill(id, payload)`。
- 失败提示优先展示后端返回错误信息。

### 3.3 校验规则

- 最小必填校验：`skillCode`、`displayName`。
- 空值时在字段下方展示错误文案，阻止提交。

## 4. 验证范围

1. 单测覆盖：加载、创建、编辑。
2. 管理端前端构建通过。
3. CDP 页面验证新增与编辑弹窗可见、可提交，并产出截图证据。
