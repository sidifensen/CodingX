# 系统配置与密钥统一化验收标准

## 目标

验证后端业务配置改为系统配置表唯一来源，AI / Web Search 等敏感密钥已加密存储，`.env` 仅保留主密钥与基础设施配置，`application.yml` 中 `app.*` 自定义配置显著精简。

## 功能验收

1. 系统配置表新增敏感配置字段后，数据库结构、迁移脚本与 `schema.sql` 保持一致，且新增表字段均包含中文注释。
2. 后端提供统一密钥加解密服务，主密钥从 `APP_CONFIG_MASTER_KEY` 读取；主密钥缺失或非法时，应用在启动阶段明确失败。
3. `setting` 表中的敏感配置使用密文存储，管理端接口返回值不包含明文，只返回脱敏值。
4. 运行时读取 AI / Web Search 等敏感配置时，后端能正确解密并供业务使用。
5. 普通业务配置从系统配置表读取，不再依赖 `application.yml` 中已迁移的 `app.*` fallback。
6. `application.yml` 中 `app.*` 仅保留启动期桥接配置或确实无法迁表的最小集合。
7. `docs/features` 功能文档更新后，明确说明配置分层、主密钥约束与敏感配置管理方式。

## 安全验收

1. 敏感配置保存到数据库后，`setting_value` 不存放对应明文。
2. 管理端查询系统配置列表时，敏感项显示脱敏值，不可回显原文。
3. 更新敏感项时，未提供新值不会清空旧密文；提供新值后会重写密文与脱敏值。
4. 后端日志、异常响应和测试快照不得输出敏感明文。

## 回归验收

1. 后端编译通过：`mvn compile`
2. 后端测试通过：`mvn test`
3. 与系统配置相关的单元测试覆盖普通配置、敏感配置、主密钥缺失 / 解密失败分支。
