# CodingX 项目概要、核心功能与目标

更新时间：2026-05-12

## 一、项目概要

CodingX 是一个面向“任务执行”的智能体平台，而不是单纯聊天工具或仅限本地开发的工具。  
用户提交的是任务目标，系统围绕目标持续进行规划、工具调用、执行、产物生成与状态回传，并支持后台长任务运行与后续接管。

产品形态采用：

- 用户端 Web（主入口）
- 用户端 Desktop（Electron，本地能力增强）
- 管理端 Web（平台治理）
- 云端与本地双执行环境（统一任务模型）

核心定位是：在统一产品框架下，同时支持代码开发与日常办公两类任务场景。

项目功能概述如下：

### 1. 任务与工作台

- 任务创建、任务列表、任务详情
- 每个任务绑定独立 Workspace
- 工作台展示目标、计划、步骤、事件流、产物
- 支持暂停、继续、重试、回看

### 2. 后台持续执行

- 多任务并发执行
- 页面关闭后任务可继续运行
- 状态持久化与恢复
- 需要人工确认时触发通知与接管

### 3. 模式化体验

- 代码开发模式
- 日常办公模式
- 同一套平台与导航框架，模式主要影响推荐任务、工具策略与工作台重心

### 4. 智能体、技能与团队

- 预设智能体（如开发、文档、研究、分析等）
- 技能系统（安装、启用、绑定）
- 团队模式（多角色协作执行同一任务）

### 5. 工具与连接能力

- 内置工具体系（搜索、文件、文档、表格、命令、代码处理等）
- MCP 外部扩展能力接入与管理
- 清晰区分“平台内置工具”与“外部 MCP 能力”

### 6. 跨宿主统一前端

- Web 与 Desktop 共用一套前端页面与任务模型
- 采用 Capability-based UI，根据环境能力动态展示控件
- 避免两套割裂产品体验

## 二、项目目标

### [A] 产品目标

- 构建 Web-first 的任务型智能体平台
- 提供可规模化的“任务执行 + 工作台回看 + 自动化”闭环
- 支持从通用任务到专业编码任务的统一承载

### [B] 能力目标

- 支持复杂任务拆解、规划、执行与验证
- 支持多任务并发与长时后台运行
- 支持技能、内置工具、MCP、预设智能体、团队协同
- 支持云端执行与本地执行共存

### [C] 体验目标

- 用户感知“平台在执行任务”，而不是只返回一段文本
- 任务过程透明可追踪（状态、日志、证据、产物）
- 可中断、可恢复、可复盘

### [D] 阶段目标（当前）

当前阶段优先完成第一条最小闭环：

- 用户创建任务
- 自动创建并绑定 Workspace
- 任务进入执行路由（先支持 mock cloud）
- 任务状态流转（queued -> running -> completed）
- 工作台实时展示状态与产物占位

这条闭环打通后，再逐步扩展桌面端本地执行、专业编码工作台、技能/MCP/团队与管理端能力。

## 三、后端技术基线

- Java：Java 25
- 框架：Spring Boot
- 认证鉴权：Sa-Token
- 实体与样板代码：Lombok
- 通用工具库：Hutool
- HTTP 客户端：OkHttp
- ORM：MyBatis-Plus
- 数据库：PostgreSQL
- 缓存：Redis
