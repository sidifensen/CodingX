# MewCode 能力缺口治理工作台设计

## 范围

本次按 `docs/project/mewcode-capability-gap-roadmap.md` 的推荐开发顺序实现前 5 项能力：Plan / Checklist 开发模式、Slash Command 命令框架、权限策略中心、Hook 生命周期机制、项目代码索引与仓库画像。最后 3 项“上下文压缩与长期记忆、真实 SubAgent 与 Worktree 并行隔离、Agent Teams”不在本轮实现范围内。

## 目标

把 CodingX 的 Web / Electron 聊天工作区升级为可治理的本地开发工作台：用户在软件端选择本地仓库后，可以通过可见命令入口启动常用开发流程；模型执行本地工具前必须经过策略判定；任务过程中的计划步骤、Hook 事件和项目画像可被后端记录，并由管理端集中查看与配置。

## 架构

后端新增 `governance` 应用层，统一承载命令目录、权限策略、Hook 规则、审计记录和项目画像。该模块不直接执行工具，而是给聊天流程和本地工具执行器提供判定、记录和查询能力。数据库新增治理相关表，`schema.sql` 与迁移脚本保持一致，并为表与字段补齐中文注释。

用户端继续复用现有聊天页和 Electron host bridge。新增 slash command 目录接口后，聊天输入区可以展示内置命令并把结构化命令提交到后端；后端将命令转换成明确的系统执行意图，避免前端自行改写业务语义。Electron 侧保留本地目录选择和本机确认，最终执行权限仍以后端策略为准。

管理端新增“治理中心”页面，采用 Ant Design 与现有主题令牌，分区展示权限策略、最近审计、Hook 规则、项目画像和内置命令。页面不使用原生弹窗，新增/编辑/删除都使用 AntD Modal，并支持亮色/暗色模式和滚动条主题。

## 核心流程

1. 用户在聊天输入区输入 `/` 或点击命令入口时，前端调用 `/api/chat/slash-commands` 获取启用命令；用户选择 `/review`、`/fix-test`、`/commit` 或 `/generate-doc` 后，前端把 `slash_command` 结构化消息提交到现有聊天流接口。后端 `ChatStreamRequestApplicationService` 解析命令类型，命中内置命令时追加命令提示上下文，并保留原始自然语言正文。命令不存在或被禁用时，后端通过统一异常返回中文 `ApiResponse.message`。

2. 模型在本地工具循环中调用 `update_plan` 时，工具执行器解析步骤数组并返回结构化结果。`ChatApplicationService` 识别 `update_plan` 工具结果，将每个步骤写入 `chat_execution_step`，`step_type=plan`，状态按 `pending/in_progress/completed` 映射为 `PENDING/RUNNING/COMPLETED`。前端继续消费现有 `step` SSE 事件，计划步骤会与搜索、MCP、工具步骤一起进入过程时间线。

3. 模型调用命令、文件写入、编辑或补丁工具前，`ChatToolExecutionService` 把规范化后的工具编码、参数、当前工作目录交给权限策略服务判定。策略服务先读取启用策略，再按工具编码、命令关键字和路径模式匹配，输出 `ALLOW`、`CONFIRM` 或 `DENY`。`DENY` 直接抛出中文业务异常并写审计；`CONFIRM` 在当前 MVP 中按“需要确认，先拒绝执行”处理，后续可接 Electron 用户确认；`ALLOW` 放行并记录审计。

4. 工具调用前后和任务完成时，聊天流程调用 Hook 服务记录生命周期事件。Hook 规则可配置触发点、条件关键字和动作类型；MVP 的动作只写审计日志，不直接执行外部命令，避免 Hook 绕过权限策略产生副作用。管理端能看到规则启停状态与最近触发日志，失败时日志记录错误原因但不中断聊天主流程。

5. 用户或管理端请求项目画像时，后端读取已绑定本地工作空间目录，扫描仓库根目录、构建文件、包管理文件和测试入口，生成模块摘要、技术栈线索和建议验证命令。画像写入数据库后，聊天侧可按工作空间读取最近画像并注入简要上下文；管理端可刷新指定工作空间画像并查看结果。扫描只读取仓库内文本和文件名，不修改本地文件。

## 数据结构

- `governance_permission_policy`：权限策略表，记录工具编码、命令模式、路径模式、动作、启用状态和说明。
- `governance_permission_audit`：权限审计表，记录一次工具调用的用户、会话、工具、工作目录、风险等级、策略动作和处理结果。
- `governance_hook_rule`：Hook 规则表，记录触发点、条件、动作类型、动作配置、启用状态和排序。
- `governance_hook_audit`：Hook 触发审计表，记录规则、触发点、会话、运行、状态和错误信息。
- `governance_project_profile`：项目画像表，按工作空间保存扫描摘要、技术栈 JSON、入口 JSON、验证命令 JSON 和最近扫描状态。
- `governance_slash_command`：内置 slash command 表，记录命令编码、名称、说明、提示模板、启用状态和排序。

## 错误处理

后端接口统一返回 `ApiResponse`，未知异常继续走全局异常处理器。治理服务所有可展示错误均使用中文，例如“当前操作需要确认后再执行”“命令命中禁用策略，已拒绝执行”“工作空间目录不存在，无法生成项目画像”。管理端和用户端 API 层只消费后端 `message`，页面不重复解析原始 `response.json()`。

## 前端设计

管理端治理中心采用运维型信息架构：顶部是紧凑工具栏与关键统计，主体用 Tabs 分为权限策略、Hook、项目画像、Slash Command 和审计，不使用卡片套卡片。策略和 Hook 以表格为主，详情用抽屉或弹窗；画像区用左右分栏展示工作空间列表和扫描摘要。视觉方向沿用当前管理端的中性工作台风格，使用现有主题令牌、AntD 控件和统一滚动条。

用户端聊天输入区新增命令提示时，只展示命令名称、说明和适用场景，不恢复旧 MCP 斜杠面板。命令选择后以轻量 tag 形式进入输入区，用户仍可补充自然语言要求。暗色模式下命令面板背景、边框、悬浮态和滚动条必须使用主题变量，不出现透明叠底。

## 测试策略

后端先写权限策略判定、slash command 查询、Hook 记录、项目画像扫描和 `update_plan` 持久化的失败测试，再实现生产代码。前端先写管理端 API/页面测试和用户端命令面板测试，再实现 UI。涉及前端交互后，最终需要执行前端构建与浏览器/CDP 验证，并保存截图到 `logs/`。
