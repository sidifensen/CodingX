# Trae Solo 风格云端 Workspace 设计

日期：2026-05-12

## 1. 文档目标

本文件用于明确本项目云端环境的核心产品约束：

- `Trae Solo` 作为云端环境参考
- 每个任务拥有独立的云端 workspace
- 任务与 workspace 强绑定

这份文档不是在讨论“云服务器怎么租”，而是在定义产品和架构层面的 workspace 模型。

## 2. 设计结论

本项目的云端环境第一优先级不参考“共享式长期云开发机”，而优先参考 Trae Solo 当前表现出来的任务级隔离机制。

核心结论如下：

- 每个任务一个独立 workspace
- 每个 workspace 只服务于一个任务
- 不同任务默认不共享文件上下文
- 不同任务默认不共享中间产物
- 不同任务默认不共享执行状态

也就是说，云端环境的主语义单位不是“一个用户的一台长期远程机器”，而是“一个任务对应一个独立工作空间”。

## 3. Workspace 与 Task 的关系

### 3.1 一对一关系

当前阶段默认采用：

- 一个 `task`
- 对应一个 `workspace`

这意味着：

- 任务创建时生成 workspace
- 任务结束后 workspace 进入保留或回收状态
- 任务列表中的每个任务，都有自己独立的文件上下文

### 3.2 为什么不做共享工作区

因为当前产品目标强调：

- 多任务后台运行
- 任务隔离
- 文件和产物可回看
- 任务审计
- 模式切换下的稳定行为

如果多个任务共享一个长期云工作区，会带来：

- 文件互相污染
- 任务上下文交叉
- 回放困难
- 审计困难
- 用户心智混乱

因此当前阶段不采用“所有任务共享一个云工作区”的设计。

## 4. 一个 Workspace 至少包含什么

每个 workspace 至少应包含以下内容：

- 任务输入文件
- 中间执行文件
- 最终交付产物
- 执行日志
- 任务上下文快照
- 可选的代码仓库副本
- 可选的引用资料副本

从用户视角看，workspace 不是抽象概念，而是“这个任务的专属工作区”。

## 5. 生命周期设计

### 5.1 创建

当用户创建并提交任务时：

1. 创建 task
2. 创建 workspace
3. 为 workspace 分配唯一标识
4. 初始化输入材料
5. 分配执行环境

### 5.2 运行

运行过程中，workspace 负责承载：

- 文件写入
- 中间产物生成
- 日志累积
- 状态快照
- 参考资料缓存

### 5.3 完成后保留

任务完成后，不应立即把 workspace 完全删除。建议先进入“已完成保留态”，用于：

- 查看产物
- 查看工作区文件
- 任务追问和延续
- 失败复盘

### 5.4 回收

在保留期结束后，可以回收：

- 执行容器
- 临时缓存
- 非必要中间文件

但应按策略保留：

- 最终产物
- 关键日志
- 状态摘要
- 必要的恢复元数据

## 6. 云端执行单元与 Workspace 的关系

当前推荐模型是：

- 一个任务
- 一个 workspace
- 一个隔离执行环境

执行环境可以是：

- Docker 容器
- sandbox worker
- 远程 runtime

但无论底层是什么，前端和平台层看到的都应是：

- 这是任务的 workspace
- 不是平台通用共享盘

## 7. 多任务并发规则

在多任务并发时，必须满足：

- 任务 A 的 workspace 不影响任务 B
- 任务 B 的产物不写入任务 A
- 任务 C 的日志不出现在任务 D
- 不同任务的依赖安装和执行环境默认互不影响

这是多任务后台运行成立的基础。

## 8. 文件与产物视角

参考你观察到的 Trae Solo 行为，workspace 不只是运行时技术对象，它还是用户可见的产品对象。

因此平台应支持：

- 查看 workspace 内容
- 浏览任务产物
- 区分中间文件与最终产物
- 在任务视图中查看该 workspace 当前状态

这会让用户理解：

- 为什么不同任务的文件不一样
- 为什么一个任务生成的文件不会自动跑到另一个任务里
- 为什么这个任务结束后还能继续看到它自己的产物

## 9. 与本地执行环境的关系

本地执行环境也可以有 workspace 概念，但语义不同：

- 本地执行 workspace 更接近用户机器上的真实目录
- 云端执行 workspace 更接近平台管理的隔离工作区

两者共同点：

- 都围绕任务组织上下文

两者不同点：

- 本地 workspace 直接依赖用户文件系统
- 云端 workspace 由平台控制生命周期和隔离边界

## 10. 当前阶段推荐实现

当前阶段建议：

- 每个云端任务创建独立 workspace 目录
- 每个任务绑定独立执行环境
- 执行完成后保留 workspace 元数据和最终产物
- 中间缓存按策略回收

如果底层用容器实现，则更具体地说：

- 一个任务一个容器
- 一个任务一个 workspace 目录
- 容器挂载该任务专属 workspace

## 11. 最终判断

本项目的云端环境设计，应优先采用：

- Trae Solo 风格的任务级 workspace

而不是优先采用：

- 用户级共享长期工作区

这意味着：

- 云端环境首先是“任务级独立执行空间”
- 然后才是“是否进一步演化为长期云工作区”
