# Phase 1 Frontend Vite+ Shell

更新时间：2026-05-13

## 一、背景

`frontend` 当前是普通 `Vite + React + Tailwind CSS` 工程，带有 AI Studio / Gemini 的脚手架残留，不符合项目要求的 `React + Vite+ + Tailwind CSS` 统一前端骨架。

同时，现有页面已经包含可复用的展示内容，但外壳层信息架构仍偏演示稿，导航入口与项目既定规划不一致。

## 二、本次目标

- 将 `frontend` 从普通 Vite 工程迁移到 `Vite+`
- 保留现有页面主体内容，不重写原业务展示页
- 新建正式 Web Shell，统一顶部栏和侧边栏组件
- 将导航骨架调整为：
  - `任务`
  - `专家`
  - `技能`
  - `工具`
  - `MCP`
  - `自动化`
- 清理 AI Studio / Gemini 残留配置与依赖

## 三、范围

本次只处理前端壳层与工具链，不扩展真实后端交互，不重写各页面主体内容，不引入 Electron 特有逻辑。

## 四、实现策略

1. 先迁移工具链到 `Vite+`
2. 为新壳层补最小测试，验证导航和默认路由
3. 抽离新的顶部栏和侧边栏组件
4. 新增 `任务 / 工具 / MCP` 占位页
5. 复用原 `Experts / Skills / Automations / TaskDetail` 页面主体

## 五、完成标准

- `frontend` 可通过 `Vite+` 正常安装、检查、测试、构建
- 默认首页进入 `任务` 页面
- 顶部栏与侧边栏均为独立组件
- 原有 `Experts / Skills / Automations / TaskDetail` 页面内容保持可访问
- `工具` 与 `MCP` 入口已在导航中存在并可访问

## 六、开发端口与组件化约束

- 前端开发服务固定端口：`5002`
- 后端开发服务固定端口：`5001`
- 前端所有新功能实现必须优先组件化拆分，避免在 `App` 或单一页面中堆叠过多职责
- 组件拆分要求：
  - 视图层组件仅负责展示与交互编排
  - 业务逻辑优先下沉到 `hooks` 或 `api / utils` 模块
  - 样式优先跟随组件文件职责归属，不跨组件混写
