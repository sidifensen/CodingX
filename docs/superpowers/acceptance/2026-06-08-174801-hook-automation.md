## Criteria

| ID | Description | Test Type | Preconditions | Expected Result |
|----|-------------|-----------|---------------|-----------------|
| AC-001 | Hook audit persistence is removed from the database baseline. | Logic | Read `backend/src/main/resources/db/schema.sql`. | The file does not contain `CREATE TABLE IF NOT EXISTS governance_hook_audit`, `COMMENT ON TABLE governance_hook_audit`, or `idx_governance_hook_audit_created`. |
| AC-002 | Existing databases drop the old Hook audit table through migration. | Logic | Read migration files under `backend/src/main/resources/db/migration`. | A new migration contains `DROP TABLE IF EXISTS governance_hook_audit`. |
| AC-003 | Built-in Hook seed rows cover start, confirm-required, failed, and completed task events. | Logic | Read baseline schema or governance migration SQL. | Seed SQL contains `BEFORE_TASK_START`, `TASK_CONFIRM_REQUIRED`, `TASK_FAILED`, and `TASK_COMPLETED` Hook rules. |
| AC-004 | `HookRuleService.trigger` returns matching enabled Hook rules without writing audit records. | Logic | Run the targeted backend HookRuleService test. | The test passes and verifies matched rules are returned in sort order with no `GovernanceHookAuditRepository` dependency. |
| AC-005 | Admin governance API no longer exposes Hook audit endpoints. | Logic | Compile backend and run governance/API tests. | `GET /api/admin/governance/hook-audits` handler and `GovernanceHookAudit` response usage are absent from source. |
| AC-006 | Admin Governance Center no longer fetches or displays Hook audit data. | Logic | Run targeted admin API/page tests or frontend build. | `listHookAudits` is absent from `AdminChatApi`, and the page only displays permission audit records in the audit tab. |
| AC-007 | Existing permission audit behavior is preserved. | Logic | Run backend permission policy tests. | Permission audit tests still pass and `governance_permission_audit` remains in schema. |

## Self-Review

- Each criterion maps to a concrete file inspection or test command.
- Criteria avoid browser-only checks because this scope removes an admin section and does not introduce a new interaction pattern.
- Sidebar task completion reminders remain out of scope and continue to use `chat_conversation.task_completion_read`.
