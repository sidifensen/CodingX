# 管理端工作空间管理设计

## 背景

当前 `workspace` 表已经承载云端历史空间与本地目录空间，但管理端没有入口查看空间归属、运行目标、仓库/目录上下文和关联会话规模。排查用户“会话在哪个空间”“本地目录是否绑定”“默认云端历史是否混入本地空间”等问题时，需要直接查库或结合用户侧页面推断。

用户要求直接实现，不再进入人工确认。因此本轮采用 autonomous 模式，范围收敛为安全的只读管理能力，不引入工作空间删除、编辑或迁移等尚未明确业务规则的写操作。

## 推荐方案

本轮采用“只读列表 + 筛选 + 会话数量统计”的方案。

备选方案一是直接复用用户侧工作空间接口，但用户侧接口带有创建默认云端空间和登录用户归属语义，不适合管理端全局排查。备选方案二是一次性做完整 CRUD，但删除和编辑会影响聊天历史归属，缺少审计、确认和迁移规则，风险高。推荐方案能快速补齐管理端可观测能力，并保持数据安全。

## 后端设计

- 新增管理端工作空间控制器，路径为 `GET /api/admin/workspaces`。
- 新增工作空间管理应用服务，负责分页参数归一化、运行目标筛选、关键字过滤、运行目标中文标签和会话数量聚合。
- 新增工作空间管理响应对象，字段包含 `id`、`name`、`repositoryUrl`、`branchName`、`workingDirectory`、`runtimeTarget`、`runtimeTargetLabel`、`createdBy`、`conversationCount`、`createdAt`、`updatedAt`。
- 扩展 `WorkspaceRepository` 和 `WorkspaceRepositoryImpl`，提供管理端只读分页查询能力；该能力必须只读取 `deleted = 0` 记录，不调用 `ensureDefaultCloudWorkspace`，避免管理端页面产生数据写入副作用。
- 复用现有 `PageResult` 分页结构和 `ApiResponse` 包裹结构，错误继续交给全局异常处理器返回中文文案。

## 前端设计

- 在管理端侧边栏新增“工作空间”菜单，路由为 `/workspaces`。
- 在 `AdminChatApi` 中新增 `listWorkspaces` 方法，集中拼接 `current`、`size`、`keyword`、`runtimeTarget` 查询参数，并复用统一响应解析。
- 新增 `WorkspacePage`，包含统计卡片、关键词搜索、运行目标筛选、刷新按钮、统一表格卡片、分页、加载骨架、错误提示和空态。
- 页面只使用项目设计令牌和已有组件，必须支持浅色与暗色模式，不使用浏览器原生弹窗。
- 表格展示工作空间名称、运行目标、创建人、会话数、仓库地址、分支、本地目录、创建/更新时间。长路径使用截断和 `title` 保留完整信息。

## 数据与兼容

本轮不涉及数据库结构变更，不新增迁移脚本。工作空间表和字段注释已存在于 `schema.sql` 与历史迁移中。

关键兼容要求：

- `runtime_target` 只支持 `cloud` 和 `local`，页面显示为“云端”和“本地”。
- 不依赖旧 `workspace_type` 字段。
- 会话数量只统计未删除会话。
- 空值字段前端显示为 `-`，避免出现 `undefined`。

## 测试策略

- 后端控制器测试覆盖 `/api/admin/workspaces` 分页响应、运行目标筛选参数透传和字段序列化。
- 后端服务测试覆盖分页归一化、运行目标标签、关键字/类型过滤后的分页结果和会话数量。
- 前端 API 测试覆盖请求路径、查询参数和分页响应解析。
- 前端页面测试覆盖列表渲染、筛选触发、加载骨架、空态和错误提示。
- 完成后按前后端改动执行 `mvn compile`、`mvn test`、`npm run build`、`npm run test:run`，再启动后端并打开前端页面检查。

## 自检

- 无 `TBD`、`TODO` 或未定义范围。
- 未引入数据库结构变化，因此不需要迁移脚本。
- 范围保持单一：管理端工作空间只读可观测。
- 写能力明确排除，避免误伤业务数据。
