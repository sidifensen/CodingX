# 工具轮次正文延迟发布修复计划

## 目标

修复模型在 `streamChatWithTools` 工具调用轮次中输出的过程正文被提前展示给用户的问题，避免 `web-access` 等技能链路把“现在执行”“检测到查询失败”等内部执行说明落到聊天消息正文。

## 执行步骤

1. 在 `ChatApplicationToolCallFlowTest` 中补充回归覆盖：带工具调用轮次的正文不发布、不落库，也不作为“已发布正文”回灌给下一轮模型。
2. 修改 `ChatApplicationService` 的工具调用循环：每轮工具流单独收集 `deferredContentDeltas`，仅在该轮没有工具调用时 flush 到 SSE 和最终消息。
3. 工具轮次存在真实工具调用时丢弃延迟正文，只追加工具执行证据；轮次上限失败时使用通用失败正文，不再保留被隐藏的中间过程正文。
4. 更新本地工具运行时文档，记录工具正文延迟发布边界和验证命令。
5. 执行定向测试与后端编译，确认修复不破坏本地工具调用主链路。
